This report distinguishes official documentation, inspected installed APIs, live
protocol evidence, and simulated tests. The smoke fixtures establish adapter
capability, not complete DevGod delivery or trustworthy candidate hashing.

## Dependencies and API

Installed from the package index on 2026-09-12 in `/tmp/devgod-sdk-spike`:

- `openai-codex==0.154.0`, with `openai-codex-cli-bin==0.154.0`.
- `mcp==2.2.0` and `mcp-types==2.2.0`.
- Spike Python 3.13.5; production package and focused tests Python 3.12.3.

The official SDK documentation confirms a stable Python package controlling the
local app server, an included compatible runtime, and sync/async clients. The
runtime may be overridden deliberately, but DevGod uses the pinned dependency.
[Official Codex SDK documentation](https://learn.chatgpt.com/docs/codex-sdk).

Inspection of the installed 0.154.0 package established these exact interfaces:

| Operation | Supported Python interface |
| --- | --- |
| Runtime configuration | `CodexConfig(cwd=..., env=..., config_overrides=(...), launch_args_override=(...))` |
| Typed protocol | `CodexClient(config, approval_handler=...)`; `start()`, `initialize()`, `request(method, params, response_model=...)`, `close()` |
| Non-generating check | `request("command/exec", {...}, response_model=CommandExecResponse)` |
| Check cancellation | `request("command/exec/terminate", {"processId": ...}, response_model=CommandExecTerminateResponse)` |
| High-level thread | `AsyncCodex.thread_start(...)`, `thread_resume(thread_id, ...)` |
| Structured result | `AsyncThread.run(input, output_schema=...)` returns `TurnResult` |
| Streaming/control | `AsyncThread.turn(...)`, then `handle.stream()`, `handle.interrupt()` |
| Low-level review | `thread_start(params)`, `turn_start(thread_id, input, {"outputSchema": ...})`, `next_turn_notification(turn_id)`, `turn_interrupt(thread_id, turn_id)` |
| Authentication status | `account_read({"refreshToken": False})`; no credential access required |
| MCP server | `from mcp.server import MCPServer`; `server.run()` or `await server.run_stdio_async()` |

`CommandExecResponse` has `exit_code`, `stdout`, and `stderr`. Streamed commands
use a connection-scoped `processId`, `streamStdoutStderr=true`, `timeoutMs`, and
`outputBytesCap`. Notifications carry base64 bytes and a truncation flag; streamed
bytes are absent from the final buffered response. `TurnResult` includes status,
error, final response, items, usage, and timing. The public high-level SDK exposes
`deny_all` and `auto_review` approval modes; the latter is its thread-start default.

The installed low-level client's default callback accepts command and file-change
approval requests. DevGod supplies an explicit deny callback for every client.
No default SDK callback can grant additional permissions. Check sandboxes permit
the active repository and a private per-invocation scratch directory, disable
network access, and exclude shared `/tmp` and inherited temporary-directory roots.

## Reviewer isolation and model settings

The adapter reads effective configuration without launching a model turn, disables
each discovered external MCP/plugin/app entry for the reviewer, and disables app
integration, web search, and recursive delegation. It checks the resulting MCP
inventory instead of assuming that an empty configuration table clears merged
settings. Repository execution configuration is inert in the frozen snapshot.
Relevant code conventions remain review data. The original repository's resolved
model, provider name, service tier, reasoning effort, and verbosity are copied
narrowly; provider transport settings, MCP commands, plugins, and hooks are not
copied. `Policy.review_model` overrides the inherited model when explicitly set.

`DEVGOD_MANAGED_REVIEW=1` suppresses DevGod's own hooks. Unrelated trusted user and
managed hooks remain subject to host policy. Their behavior is not proven by the
MCP/notification startup probe. Configured plugin disablement does not override
workspace-managed enabled states; the inventory check fails closed if external
tools remain available. [Configuration reference](https://learn.chatgpt.com/docs/config-file/config-reference),
[hook trust and managed hooks](https://learn.chatgpt.com/docs/hooks).

## Process ownership and crash recovery

Closing the SDK connection alone cannot prove that detached command descendants
stopped. An initial process-session design was rejected after a regression test
demonstrated a live child escaping with `setsid()`. The final Linux supervisor is
a subreaper: it launches only the pinned Codex app server, inherits protocol stdio,
and remains alive while terminating and reaping all descendants, including
reparented children that created separate sessions. Only `waitpid` reporting
`ECHILD` permits a durable, nonce-bound cleanup receipt. Repository commands still
execute exclusively through Codex's sandboxed `command/exec` API.

Before dispatch, the adapter records the supervisor PID, process-group/session
IDs, kernel birth ticks, boot ID, and private receipt location/nonce. A parent-death
signal triggers cleanup if the MCP process dies; the supervisor also checks parent
identity after installing that signal to cover startup races. Restart recovery
accepts an exact observed receipt or a prior boot, or signals the still-matching
supervisor through a PID descriptor and waits for its receipt. A missing or killed
supervisor without a receipt remains ambiguous and cannot authorize a retry.
Unknown invocation IDs cannot obtain termination proof.

Receipts live under the external DevGod state directory, outside the active
repository, reviewer snapshot, and command scratch. Ambient `TMPDIR` cannot choose
this location. The adapter rejects symlink ancestors, nonprivate state ownership,
invalid receipt files, and production installations whose own code, SDK, or
bundled runtime reside inside the consuming repository's writable tree. Public
status and evidence packets omit the receipt nonce. This boundary protects against
managed repository checks; it is not protection from a separate unrestricted
process running as the same OS user.

The public SDK supports the supervised launch through `launch_args_override`.
Two isolated implementation seams depend on pinned SDK internals: observing
`CodexClient._proc.pid` before dispatch, and releasing `_router.fail_all` queue
waiters if cleanup remains unresolved. The latter prevents a timeout from hanging
the manager without killing the reaper or manufacturing termination evidence.
Dependency upgrades must revalidate both seams. Capabilities honestly report
`linux-subreaper-receipt`; other platforms do not advertise managed execution.

Real OS regression tests exercise detached children, hard parent death, and a
hard-killed supervisor. Contract tests separately exercise PID reuse, malformed,
symlinked, oversized and FIFO receipts, incorrect nonces, runtime placement,
receipt directory placement, and bounded unresolved output cleanup. These tests
do not consume model-generated evidence.
